A frosted panel, a button that grows when you hover it, a spinner that never stops: **standard CSS effects, animations and transitions work on BUI's Rust side.** The math follows the W3C specs, and a page that isn't moving costs no CPU at all.

## Effects at a glance

<Figure
  shot="feature-html-effects"
  alt="CSS effects on a gradient landscape: grayscale, sepia, hue-rotate, blur and drop-shadow filters; circle, polygon and star clip-paths; rotate, skew and scale transforms; multiply, screen and difference blend modes; and a backdrop-filter panel"
  caption="Filters, <code>clip-path</code>, 2D transforms, <code>mix-blend-mode</code> and <code>backdrop-filter</code>, drawn by BUI (<code>examples/site_effects.rs</code>)."
/>

```css
.glass   { backdrop-filter: blur(8px) brightness(1.2) }
.dim     { filter: grayscale(1) opacity(0.6) }
.ink     { mix-blend-mode: multiply }
.avatar  { clip-path: circle(40%) }
.fade    { mask-image: linear-gradient(to right, #000, transparent) }
.tilted  { transform: rotate(-3deg) scale(1.05) }
.framed  { border: 10px solid; border-image: linear-gradient(#4772b3, #7a4fb3) 10 }
```

Put any of these in a `style()` sheet, a `.style(...)` call, or the matching Tailwind classes, and they work as written.

## Filters

`filter` and `backdrop-filter` take a list of these functions:

| Function | Effect |
| --- | --- |
| `blur(px)` | A Gaussian blur (three box-blur passes, the approximation browsers use) |
| `brightness()`, `contrast()`, `saturate()` | Light, contrast and color intensity |
| `grayscale()`, `sepia()`, `invert()` | Recoloring |
| `hue-rotate(deg)` | Rotate every hue |
| `opacity()` | Fade |
| `drop-shadow(x y blur color)` | A shadow that follows the shape's pixels |

`filter` changes the element itself. `backdrop-filter` (and `-webkit-backdrop-filter`) changes what's *behind* it: that's the frosted-glass look.

## Blend modes

`mix-blend-mode` supports all 16 modes, `normal`, `multiply`, `screen`, `overlay`, `darken`, `lighten`, `color-dodge`, `color-burn`, `hard-light`, `soft-light`, `difference`, `exclusion`, `hue`, `saturation`, `color` and `luminosity`, plus `plus-lighter`. `isolation` works too.

An element blends with whatever was painted before it; blending across stacking contexts is <ComingSoon inline />.

## Clip paths and masks

- **`clip-path`:** `inset()`, `circle()`, `ellipse()`, `polygon()`, and reference boxes. `path()` is <ComingSoon inline />.
- **`mask` / `mask-image`:** gradients and PNGs, as alpha or luminance, with `mask-size`, `mask-position` and `mask-repeat`.
- **`clip: rect(...)`** works on absolutely positioned boxes, as in CSS 2.1.

## Transforms

Every 2D transform draws: `translate`, `scale`, `rotate`, `skew`, `matrix`, with `transform-origin`, and the individual `rotate`, `scale` and `translate` properties.

```css
#bar   { transform: rotate(90deg) }      /* about its center, by default */
#badge { scale: 2 }
#card  { transform: skewX(12deg) }
```

<Callout type="warning" title="Clicks use the untransformed box">
2D transforms change how an element looks, not where it's clicked: hit testing still uses the box before the transform. 3D transforms (`perspective`, `rotateX`, `rotateY`, `matrix3d`) have no effect yet.
</Callout>

## Borders, outlines and decorations

These render too, beyond solid lines:

- **Every `border-style` and `outline-style`:** `dashed`, `dotted`, `double`, `groove`, `ridge`, `inset`, `outset`. They follow rounded corners, using Blender's corner tessellation.
- **`border-image`:** gradients and PNGs, with `slice`, `width`, `outset`, `stretch` / `repeat` / `round` / `space`, and `fill`. It draws the nine slices.
- **Text decoration:** `text-decoration-style` (including `wavy`), `text-decoration-thickness` and `text-underline-offset`.
- **Backgrounds:** `background-clip` and `background-origin` (`border-box`, `padding-box`, `content-box`), `background-attachment: fixed`, and `background-image: url()` (any [image format](/docs/concepts/images)) with `background-size`, `background-position` (and `-x` / `-y`) and `background-repeat`.
- **Generated content:** counters (`counter-reset`, `counter-increment`, `counter-set`, with `counter()` and `counters()` in `content`), `empty-cells`, `list-style-image`.

## How effects are drawn

The element's subtree is drawn offscreen with the canvas' own drawing code, then filtered, clipped, masked and resampled (bilinear, like Blender's image transform), then composited back with the W3C formulas. This works the same on the CPU and GPU renderers.

You don't have to think about the cost. BUI picks the cheapest way for each effect:

- **Moves and scales are vectors.** `scale`, `translate` and transforms that only move and scale map what the element draws (text at the new size, rectangles, images) instead of drawing it into pixels. An animated `scale` costs what an animated color does.
- **Turns and skews run on the GPU.** A `rotate`, a skew or a mirror draws the element once, and the GPU renderer turns that picture each frame. Only the matrix changes per frame; nothing is redrawn or uploaded again. The CPU renderer turns it on the CPU.
- **Wide blurs work at their own resolution.** A `blur(64px)` can't show detail finer than about a third of its radius, so it is drawn and blurred at that resolution and stretched back, hundreds of times fewer pixels. Narrow blurs are three box blurs in integers, which the compiler vectorizes.
- **Results are cached by stage.** The drawing, the filtered picture and the final image are kept separately, relative to the element. An element that only moves is never blurred again, a turning one only turns, a fading one only fades, and an animated blur radius reuses its drawing.
- **What you can't see costs nothing.** Elements outside the window or their clip are skipped.

So **a page that doesn't change costs nothing**, however many effects it has, and one that moves costs what moves. The full write-up, with measurements, is `docs/effects-performance.md` in the repository.

## Animations

`@keyframes` animations run like a browser's:

```rust title="src/main.rs"
use blenderui::prelude::*;

const CSS: &str = "
@keyframes pulse { 50% { opacity: 0.4; transform: scale(0.95) } }
.saving { animation: pulse 1.2s ease-in-out infinite }
";

struct Saving;

impl Render for Saving {
    fn render(&mut self, _: &mut Window, _: &mut Context<Self>) -> impl IntoElement {
        body().styled().child(style().child(CSS))
            .child(div().class("saving").p_4().child("Saving…"))
    }
}

fn main() {
    Application::new().run(|cx| {
        cx.open_window(WindowOptions::default(), |_, cx| cx.new(|_| Saving)).unwrap();
    });
}
```

What's supported:

- **Keyframes:** percentage lists, `from` / `to`, `@keyframes` inside `@media`, and a per-keyframe `animation-timing-function`. When a name is defined twice, the last matching block wins.
- **Every `animation-*` longhand and the `animation` shorthand:** lists of animations, negative delays, `infinite`, every direction, fill mode and play state.
- **Each element keeps its own clock.** Two elements with the same rule, added at different times, animate independently.
- **Tailwind's** `animate-spin`, `animate-ping`, `animate-pulse` and `animate-bounce` come with their keyframes.

### The animation properties

Each longhand takes a comma-separated list, one entry per animation in `animation-name`. A shorter list repeats from its start.

| Property | Values | Default |
| --- | --- | --- |
| `animation-name` | a `@keyframes` name (or a quoted string), or `none` | `none` |
| `animation-duration` | a time: `1.2s`, `300ms`, or `0` | `0s` |
| `animation-timing-function` | an [easing function](#easing) | `ease` |
| `animation-delay` | a time; negative starts partway through | `0s` |
| `animation-iteration-count` | a number of iterations (fractions work), or `infinite` | `1` |
| `animation-direction` | `normal`, `reverse`, `alternate`, `alternate-reverse` | `normal` |
| `animation-fill-mode` | `none`, `forwards`, `backwards`, `both` | `none` |
| `animation-play-state` | `running`, `paused` | `running` |
| `animation` | the shorthand: any of the above, in any order, comma-separated per animation | |

- **Fill modes:** `backwards` applies the first keyframe during the delay, `forwards` keeps the last one after the end, `both` does both.
- **Paused animations hold their place.** Set `animation-play-state: paused` and the animation stops where it is; set it back to `running` and it carries on from there.
- **Later animations win.** When two animations in one `animation-name` list set the same property, the later one wins.
- **`!important` wins over animations.** A property set by an `!important` declaration keeps its value while an animation runs.
- **An unknown name or `none` costs nothing.** No state is kept for it.

```css
.toast {
  animation: slide-in 300ms ease-out both, fade-out 200ms ease-in 3s forwards;
}
```

## Transitions

`transition` and its longhands animate a property when its value changes, for example on `:hover`:

```css
#tile       { width: 100px; background: rgb(255, 0, 0);
              transition: width 1s linear, background-color 1s linear }
#tile:hover { width: 200px; background: rgb(0, 0, 255) }
```

- **`all` or a list of properties**, and `transition-behavior: allow-discrete`.
- **Interrupted transitions start from the current value.** Leave a hover halfway, and the box shrinks back from where it is.
- **A transition sent back to where it came from takes only as long as it ran.** Half a second out means half a second back.

### The transition properties

| Property | Values | Default |
| --- | --- | --- |
| `transition-property` | `all`, `none`, or property names, comma-separated | `all` |
| `transition-duration` | a time per entry | `0s` |
| `transition-timing-function` | an [easing function](#easing) per entry | `ease` |
| `transition-delay` | a time per entry; negative starts partway through | `0s` |
| `transition-behavior` | `normal`, `allow-discrete` | `normal` |
| `transition` | the shorthand: property, duration, easing, delay and behavior per entry | |

When several entries name the same property (`all` counts), the last one wins. A property that doesn't [interpolate](#what-animates-smoothly) only transitions with `allow-discrete`: it flips at the halfway point instead of at once.

### How they stack

An element's style is built in this order, and a later layer wins:

1. The cascade: your CSS, classes and style methods.
2. Running transitions.
3. Running animations.
4. [Motion](../motion/) values: element props such as `animate` and `whileHover`, and motion values bound with `style={{ ... }}`.

## Easing

`linear`, `ease`, `ease-in`, `ease-out`, `ease-in-out`, `cubic-bezier()`, `steps()` with every jump position (`jump-start`, `jump-end`, `jump-none`, `jump-both`), `step-start`, `step-end`, and `linear()` with points.

| Function | Curve |
| --- | --- |
| `linear` | Constant speed. |
| `ease` | `cubic-bezier(0.25, 0.1, 0.25, 1)`, the default. |
| `ease-in`, `ease-out`, `ease-in-out` | `cubic-bezier(0.42, 0, 1, 1)`, `(0, 0, 0.58, 1)`, `(0.42, 0, 0.58, 1)`. |
| `cubic-bezier(x1, y1, x2, y2)` | A Bézier curve. Both `x` values must be between 0 and 1; `y` values may overshoot. |
| `steps(n)`, `steps(n, jump-start)` | `n` jumps. The position is `jump-start` (or `start`), `jump-end` (or `end`, the default), `jump-none` (needs `n` of 2 or more) or `jump-both`. |
| `step-start`, `step-end` | `steps(1, jump-start)`, `steps(1, jump-end)`. |
| `linear(0, 0.25 75%, 1)` | Straight lines through the points. Each output may take one or two input percentages; points without one are spread evenly. |

An easing function that can't be read makes the whole declaration invalid, as in a browser.

## What animates smoothly

These interpolate:

- lengths, percentages and numbers,
- colors (in premultiplied sRGB, as browsers do),
- `box-shadow` and `text-shadow`,
- `transform` (function by function), `rotate`, `scale`,
- `filter` and `backdrop-filter` (function by function),
- `visibility` and `z-index`.

Every other property flips at the halfway point.

## Zero cost when still

A window renders frames **only while something moves**. Finished or paused animations cost no CPU, and transitions alone don't wake anything until a value actually changes. You can check from code: `window.is_animating()` is `true` while animations, transitions or motions run.

**A moving frame is only a redraw.** When an animation or transition changes only how things look (opacity, colors, shadows, filters, `transform`, `rotate`, `scale`, `translate`), each frame looks up the value and repaints the boxes that changed: no render, no cascade, no layout. That is as cheap as a [Motion](../motion/) value. 300 rows with running transitions cost about 0.6 ms of BUI's work a frame. Values that change layout (a width, a margin) still render full frames.

## Animation from Rust code

CSS runs by itself. These calls let your code watch it, step it, and drive frames of its own.

| Call | On | What it does |
| --- | --- | --- |
| `is_animating() -> bool` | `Window` | Whether CSS animations, transitions or [motions](../motion/) were running at the last render. The window keeps requesting frames while they are. |
| `needs_render() -> bool` | `Window` | Whether the window will render again: something changed or is animating. |
| `request_animation_frame()` | `Window` | Render again on the next display refresh. Call it from `render` to animate from code. |
| `set_vsync(on: bool)` | `Window` | Pace frames to the display (`true`, the default). `false` renders as fast as the CPU allows, for benchmarks. |
| `start_view_transition(cx: &App)` | `Window` | Start a [view transition](#view-transitions). |
| `advance_clock(d: Duration)` | `App` | Move every window's animation clock forward by `d`. |

For animations driven by your own code instead of CSS, call `window.request_animation_frame()` from `render`: the window renders again on the next display refresh. See [Events](../events/#animating-from-code).

### The virtual clock

Headless windows run on a **virtual clock** that moves only when you call `cx.advance_clock(duration)`, so tests can step animations exactly. Native windows add the duration to real time.

```rust
use std::time::Duration;

#[test]
fn pulse_dims_halfway() {
    Application::headless().run(|cx| {
        let w = cx.open_window(WindowOptions::default(), |_, cx| cx.new(|_| Saving)).unwrap().id;
        cx.draw(w);
        cx.advance_clock(Duration::from_millis(600)); // half of 1.2 s
        cx.draw(w);
        // read pixels or element_bounds here
    });
}
```

[Headless testing](../headless-testing/#test-animations-with-a-virtual-clock) shows more.

## View transitions

A view transition animates from one state of the page to the next. Call `window.start_view_transition(cx)` in the event handler, before you change the state. BUI pictures the page as it is; the next render shows the new state, and:

- boxes with a `view-transition-name` move and resize from their old place to their new one, while their old picture fades out,
- the rest of the page cross-fades.

```rust
h.update(cx, |view, window, cx| {
    window.start_view_transition(cx);
    view.expanded = true;
    cx.notify();
});
```

```css
#hero { view-transition-name: hero }
::view-transition-group(*) { animation-duration: 0.4s; animation-timing-function: ease-out }
```

`::view-transition-group()`, `::view-transition-old()` and `::view-transition-new()` take a name, `*`, or a `.class` from `view-transition-class`. They set `animation-duration`, `animation-delay`, `animation-timing-function`, or `animation: none`. Without them each part takes 0.25 s with `ease`. A window that hasn't rendered yet has nothing to animate from, so the call does nothing.

## Reduced motion

`blenderui::set_reduced_motion(true)` turns on reduced motion for the whole app, and `blenderui::reduced_motion()` reads it back. With it on:

- `@media (prefers-reduced-motion: reduce)` matches, so your CSS can turn animations off:

  ```css
  @media (prefers-reduced-motion: reduce) {
    .saving { animation: none }
  }
  ```

- animated images (GIF, WebP) hold their frame, and Blender's panel animations jump,
- [Motion](../motion/#global-settings) jumps every property except opacity and colors to its end.

It is off by default. BUI doesn't read the operating system's setting by itself: pass it in.

## The `anim` module

`blenderui::anim` holds the types the cascade stores for these properties. Most apps never touch them. `Timing` is useful on its own, to evaluate a CSS easing curve in your own code:

```rust
use blenderui::anim::Timing;
use blenderui::css::tokenize;

let t = Timing::parse(&tokenize("cubic-bezier(0.2, 0.8, 0.4, 1)")[0]).unwrap();
let y = t.apply(0.5, false); // the eased progress halfway
```

| Item | What it is |
| --- | --- |
| `Timing` | An easing function: `Linear`, `Bezier(x1, y1, x2, y2)`, `Steps(n, StepPos)`, or `Points(Box<[(f32, f32)]>)` for `linear()` (input, output pairs, inputs rising). |
| `Timing::parse(&Tok) -> Option<Timing>` | One easing function from a CSS token (`blenderui::css::tokenize` makes them). `None` when it isn't one. |
| `timing.apply(x, before) -> f32` | The eased progress at input `x`. `before` says the animation is still in its delay, which matters for `steps()` exactly at a jump. Outside 0..1, Bézier curves carry on along their end tangents. |
| `EASE` | `Timing::Bezier(0.25, 0.1, 0.25, 1.0)`, CSS's `ease`. |
| `StepPos` | A `steps()` jump position: `Start`, `End`, `None`, `Both`. |
| `Direction` | `animation-direction`: `Normal` (the default), `Reverse`, `Alternate`, `AlternateReverse`. |
| `Fill` | `animation-fill-mode`: `None` (the default), `Forwards`, `Backwards`, `Both`. |
| `AnimSpec` | One element's `animation-*` and `transition-*` longhands, as lists (entry `i` of a shorter list is `list[i % len]`). |

| `AnimSpec` field | Type | Longhand |
| --- | --- | --- |
| `names` | `Vec<Box<str>>` | `animation-name` |
| `durations` | `Vec<f32>` (seconds) | `animation-duration` |
| `timings` | `Vec<Timing>` | `animation-timing-function` |
| `delays` | `Vec<f32>` (seconds) | `animation-delay` |
| `iterations` | `Vec<f32>` (`f32::INFINITY` for `infinite`) | `animation-iteration-count` |
| `directions` | `Vec<Direction>` | `animation-direction` |
| `fills` | `Vec<Fill>` | `animation-fill-mode` |
| `paused` | `Vec<bool>` (`true` is paused) | `animation-play-state` |
| `t_props` | `Vec<Box<str>>` | `transition-property` |
| `t_durations` | `Vec<f32>` (seconds) | `transition-duration` |
| `t_timings` | `Vec<Timing>` | `transition-timing-function` |
| `t_delays` | `Vec<f32>` (seconds) | `transition-delay` |
| `t_discrete` | `Vec<bool>` (`true` is `allow-discrete`) | `transition-behavior` |

A computed style keeps its `AnimSpec` in `Computed::anim` (`None` when the element has neither). It isn't inherited.

## Not done yet

<ComingSoon feature="The rest of CSS effects and animation">

- **Animation events:** no `animationstart`, `animationend` or `transitionend` yet. For a callback when a motion ends, use [Motion](../motion/#callbacks) from code.
- **Pseudo-elements:** no animations on `::before` / `::after`.
- **Late transitions:** an element starts a transition only if it already had a `transition` in the previous frame. A `transition` that appears only under `:hover` doesn't run on the first hover; put it on the base rule instead.
- **Mixed units:** lengths that resolve differently (`50%` to `100px`, or `auto`) flip at 50% instead of going through `calc()`.
- **Effects:** `filter: url(#svg)`, `clip-path: path()`, `mix-blend-mode` across stacking contexts, and 3D transforms.

</ComingSoon>
