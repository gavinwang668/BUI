Read this page before you pick BUI for something you will ship. Everything here is true today; the [roadmap](../roadmap/) says what is planned.

## Accessibility

- **Windows:** screen readers see BUI apps through UI Automation ([AccessKit](https://accesskit.dev)): the HTML page and the Blender widgets in one tree, with roles and names mapped as browsers map HTML and ARIA, values and states, and actions (press, toggle, set a value, increment, expand, focus). The tree is built only once a reader asks, so apps nobody inspects pay nothing.
- **macOS and Linux:** not yet (NSAccessibility and AT-SPI are next).
- **Gaps on Windows:** no text-range navigation inside fields, no Tab traversal between HTML elements (readers use their own navigation), Blender widgets other than text fields take no keyboard focus of their own, and some items (grid views, menu bars, pie menus) aren't exposed yet.
- **Bindings:** Rust (and so Node) has it on by default; the C kit's other bindings get it with the `a11y` feature, which needs cargo to build.

## Text

- The UI font is Blender's Inter, embedded and drawn with FreeType. Installed fonts are found by name. A character the font lacks is drawn from the rest of the `font-family` list, then from the system's fallback fonts for its script when one of them is installed and has it; otherwise it appears as a missing glyph. BUI doesn't search every installed font.
- Input methods (IME) work on Windows only: composed input such as Japanese or Chinese works there, and isn't expected to work on Linux (X11) or macOS yet.
- Right-to-left text is reordered but not shaped (Arabic joining), and there are no OpenType features.

More in [Text and fonts](../../concepts/text-and-fonts/).

## It doesn't look native

BUI looks like Blender. It has Blender's Dark and Light themes (other Blender theme files can't be loaded yet), and it doesn't follow your operating system's theme, accent color or fonts. If your users expect platform-native widgets, use the platform's toolkit.

## Rendering

- The **CPU rasterizer** is the default. It works everywhere and needs no GPU.
- The optional **GPU renderer** is Direct3D 11 on Windows (Direct3D 12 opt-in: `BUI_GPU_API=d3d12`) and OpenGL 3.3 on Linux.
- **macOS has no GPU renderer** (no Metal), so it always draws on the CPU.
- Vulkan, Metal and WebGPU backends don't exist yet.

## Platforms

- **Windows and Linux** (X11; native Wayland is experimental, CPU renderer only, and has no title bar on compositors without server-side decorations, such as GNOME) are the supported platforms.
- **macOS works, with limits.** CI checks it and three people have tried it by hand on Macs (two Apple Silicon, one Intel). JavaScript windows are headless there, and there is no GPU renderer. See the [macOS testing guide](https://github.com/ppmpreetham/BUI/blob/main/docs/macos-testing.md).
- The npm packages are prebuilt for **Windows x64**, **Linux x64** (glibc 2.35 or later) and **macOS**. On other systems, build the addon from source.

## Retained mode, and no visual editor

BUI keeps a tree of nodes, like Blender's own UI, and redraws only what changed. It is not an immediate-mode library. There is no drag-and-drop UI designer: you write the UI in code.

## Where the numbers come from

Every performance number on this site was measured on **one Windows 11 laptop** (Ryzen 7 5800U). Linux and macOS haven't been measured yet, so treat the comparisons as results for that machine.

## The home page demos are sketches

The interactive panel on the home page is a **JavaScript imitation** that shows the feel of the widgets in a browser, and says so. The real widgets are native. Run a [Python, Rust or JavaScript example](../../start/installation/) to try them. A Rust app can also be built for a browser `<canvas>` ([WebAssembly](../../rust/webassembly/)).

## It's a port, not Blender unchanged

BUI's widget drawing and interaction are ported from Blender's UI sources, with edits (each marked `BUI:` in the file). The rest of Blender (its data system, window manager and operators) isn't included, and there is no automated sync with Blender's releases.

## Partial areas

- **Qt syntax** covers 57% of Qt's methods on the core widget classes (`tools/qt_coverage.py`), and a few setters are accepted and ignored.
- **CSS:** 261 of 745 W3C properties render.
- **Video** sound is tested on Windows only: the macOS and Linux audio outputs, and the macOS video backend, are untried.
- **Images:** OpenEXR, AVIF and JPEG XL are built only when asked for (the `exr`, `avif` and `jxl` features, off by default: each adds about 1 MB). HEIC decodes through the operating system, so it is there only where the system has a decoder (Windows: the HEIF Image and HEVC Video Extensions), and its macOS (ImageIO) and Linux (libheif) backends are untried.
